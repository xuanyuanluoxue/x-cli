# ADR 0007：重置历史后的远端迁移与发行连续性

- 状态：已接受
- 日期：2026-07-29

## 背景

本地仓库已按当前可验证状态重新初始化为单根提交，旧 Git 对象另行离线备份。
GitHub 上仍保留旧 `dev` / `main` 历史和已发布的 `v0.7.0` Release，因此新根历史
不能继续使用 `0.7.0`，也不能通过删除标签或 Release 来伪装成同一份源码。

## 决策

1. 已发布的 `v0.7.0` 标签和 Release 保持不可变，作为旧历史的发行快照。
2. 新根历史从 `0.8.0` 开始，后续版本只从新的 `main` 创建。
3. 远端一次性迁移前，先把旧 `main` 和旧默认分支各自保存到明确的
   `archive/pre-reset-*` 只读分支；随后才允许用 `--force-with-lease` 更新
   `main`，禁止无租约的裸 `--force`。
4. 新 `main` 推送并通过 CI 后，把 GitHub 默认分支切到 `main`，启用必需检查、
   PR 审查和禁止直接推送，再删除长期 `dev`。
5. 远端迁移属于管理员外部动作，必须在得到明确的 commit / push 授权后执行，
   并在每一步重新核对远端 SHA。

## 影响

- 旧 Release 的下载地址和来源追溯保持有效。
- Git 历史从 `0.8.0` 起简洁统一，但旧克隆需要重新克隆或显式切换到新根历史。
- `archive/pre-reset-*` 只用于审计，不参与日常开发和发布。
