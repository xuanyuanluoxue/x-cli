# ADR 0006：单主干开发与可复现 Web 构建

- 状态：已接受
- 日期：2026-07-28

## 背景

仓库曾同时使用 `dev` 作为日常集成分支、`main` 作为发布分支。实际演进中，
功能直接汇入了 `main`，但远程默认分支仍指向 `dev`，本地 `dev` 也与
`origin/dev` 产生分叉。2026-07-28 审计时，本地和远程 `dev` 的提交都已被
`main` 完整包含，因此继续维护两条长期分支只会增加同步成本和误操作风险。

Web 前端源码位于 `web/`，Vite 产物提交在 `core/web/static/` 供 Python 包和
Windows EXE 使用。此前 CI 没有验证两者一致，导致原生前端遗留文件和过期哈希
产物长期留在仓库。Windows 默认换行转换也会让生成文件产生无意义差异。

## 决策

### 1. 使用 `main` 单主干

- `main` 是唯一长期分支，同时承担集成、可发布状态和版本打标签。
- 所有功能和修复都从最新 `origin/main` 创建短期
  `feature/<name>` 或 `fix/<name>` 分支。
- 所有 PR 的目标分支都是 `main`；禁止直接推送 `main`。
- PR 默认使用 squash merge，并使用中文
  `类型(模块): 描述` 作为最终提交信息。
- 分支应短期存在，合并后删除；不再创建新的长期 `dev` 或 release 分支。

### 2. 用检查保证主干始终可发布

- `main` 和面向 `main` 的 PR 必须通过 Python 全量测试。
- 修改 `web/` 时必须使用 `npm ci` 按锁文件安装依赖，再运行
  `npm run build`。
- `core/web/static/` 是提交进 Git 的发布产物，但禁止手工编辑。
- CI 重建 Web 后检查整个静态目录的 `git status --porcelain`；任何修改、
  删除或未跟踪哈希文件都使检查失败。
- 发布仍由版本标签触发，标签只能从通过 CI 的 `main` 提交创建。

### 3. 保留风险分级开发流程

单主干不等于跳过设计和验证。小、中、大/高风险变更继续遵循 `AGENTS.md`
定义的计划、BDD/TDD、ADR、聚焦测试和全量测试要求。临时计划验收后删除，
长期规则写入行为规格、ADR 或架构文档。

### 4. 固定跨平台换行

- 源码、Markdown、YAML、Web 源码和 `core/web/static/` 统一使用 LF。
- Windows PowerShell 脚本保留 CRLF。
- `.gitattributes` 是换行规则的唯一仓库级来源，不依赖开发者本地
  `core.autocrlf`。

## 远程迁移

本 ADR 入库并通过 CI 后，由仓库管理员执行一次性迁移：

1. 把 GitHub 默认分支改为 `main`。
2. 为 `main` 启用禁止直接推送、至少一次审查和必需 CI 检查。
3. 确认 `dev` 没有 `main` 之外的提交。
4. 删除远程 `dev`，并让现有克隆执行
   `git remote set-head origin --auto`。

远程设置和分支删除是外部破坏性操作，不由普通代码变更自动执行。

## 影响

- 不再需要周期性把 `dev` 合入 `main`，也不会出现两个“最新”分支。
- 每个 PR 都直接针对最终发布历史，分支与发布状态更容易判断。
- CI 时间增加，但能在合并前发现测试失败、锁文件问题和过期 Web 产物。
- 已有 Fork 需要把基础分支从 `dev` 改为 `main`。
