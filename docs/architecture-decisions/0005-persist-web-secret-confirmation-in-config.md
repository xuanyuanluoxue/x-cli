# ADR 0005: 在用户配置中持久化 Web 密钥确认偏好

- 状态：已接受
- 日期：2026-07-19

## 背景

Web 查看或编辑密钥记录前会先弹出安全确认，因为随后调用的 API 会把全部字段（包括密钥明文）交给浏览器。频繁使用时，用户希望明确选择“不再提示”，同时保留通过配置文件重新开启提示的能力。

偏好既可以只存在浏览器 `localStorage`，也可以写入 x-cli 的 `config.yaml`。但浏览器状态无法体现 x-cli 实际安全配置，清理浏览器数据或更换浏览器后也会产生不同结果；同时用户无法通过一个可审计的配置文件恢复开关。

## 决策

1. 新增顶层配置项 `web_secret_confirmation`，默认 `true`。缺失该字段、旧版 health 响应缺少能力字段或读取状态未知时，前端都继续提示。
2. WebServer 启动时接收本次运行实际使用的配置文件路径和配置值。`GET /api/health` 返回 `secret_confirmation_required`，前端以此作为当前会话的唯一状态。
3. 新增受现有 Web Token 规则保护的 `PATCH /api/preferences`。该端点只接受布尔字段 `secret_confirmation_required`，不提供通用配置键值写入能力。
4. 用户在安全确认框勾选“不再提示”并确认后，前端调用该 API。后端先原子写入当前配置文件，再把当前 WebServer 的内存状态改为 `false`，因此无需重启即可停止后续提示。
5. 配置更新采用最小文本补丁：替换或追加顶层 `web_secret_confirmation`，保留注释、未知字段、字段顺序和无关设置；通过同目录临时文件加 `os.replace` 完成原子提交。
6. 恢复提示由用户把当前配置文件中的 `web_secret_confirmation` 改为 `true` 并重启 `x web`。本期不实现配置热重载或设置页面。
7. 保存偏好失败不阻止本次已经人工确认的明文访问，但前端必须提示失败，且本地状态保持需要提示。

## 备选方案

- **只用 localStorage**：实现简单，但偏好分散在浏览器，无法通过配置文件审计或恢复，否决。
- **提供通用配置 API**：扩展性强，但显著扩大远程修改本机路径、日志和认证设置的攻击面，否决。
- **前端直接改配置文件**：浏览器没有可靠、可移植的本地文件写权限，否决。
- **每次关闭都要求重启 WebServer**：实现更简单，但“不再提示”不能立即生效，体验不符合预期，否决。
- **关闭时同时取消服务端明文日志警告**：这会隐藏真实的数据离开存储事件；偏好只控制 UI 提醒，否决。

## 影响

- 默认安全行为不变；只有用户明确勾选后才关闭提示。
- 配置文件多一个稳定、可手工编辑的布尔字段。
- health 响应增加一个向后兼容字段，API 端点增加一个窄范围写操作。
- WebServer 必须知道有效配置路径；CLI 仍不依赖 WebServer。
- 关闭 UI 提示不会改变密钥字段默认隐藏、明文 API 警告或可选 Token 认证。

## 不变量

- 密钥列表不读取或返回字段值。
- `GET /api/secrets/<name>` 继续记录明文输出警告。
- 配置开关默认开启，未知状态按开启处理。
- API 不能修改 `web_auth`、存储路径、日志或任意未知配置项。
- 配置更新失败时不改变运行时开关。
